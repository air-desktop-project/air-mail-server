air-mail-server

serveur de courrier SMTP, POP3, IMAP et HTTP

Synopsis

air-mail-server --config <fichier>
air-mail-server [--help | --version]

Description

air-mail-server reçoit, range et sert du courrier. Il parle SMTP (remise et soumission), IMAP, POP3, et une API REST sur HTTP/2 — chacun en clair avec STARTTLS ou sous TLS implicite, selon ce que la configuration ouvre.

Il ne lit aucun fichier de configuration textuel, ne consulte aucune variable d'environnement de réglage et n'accepte aucune autre option que celles ci-dessous. Sa configuration est un fichier binaire produit par air-mail-admin(8).

Deux sources de configuration seraient une de trop : un réglage qui existe à deux endroits finit par différer, et c'est toujours au mauvais moment qu'on découvre lequel des deux le serveur a cru.

Options

--config <fichier>

la configuration binaire à lire. Obligatoire. Le serveur refuse de démarrer si le fichier manque, n'est pas lisible, ou ne se relit pas.

--help

l'aide intégrée, puis sortie.

--version

la version, puis sortie.

Ce qu'il dit au démarrage

Le serveur annonce dans son journal ce qu'il sert vraiment : les protocoles ouverts, les domaines hébergés, le chiffrement, le nombre de comptes — et, surtout, ce qui manque : « EN CLAIR », « AUTH non annoncé », « aucun résolveur ».

Cette liste est relevée à l'exécution, et c'est délibéré : une liste écrite dans cette page vieillirait sans que personne ne s'en aperçoive. Pour savoir ce que cette machine-ci sert, lisez son journal ou air-mail-admin config show, jamais une documentation.

Ports, et pourquoi ils sont hauts

L'unité systemd livrée tourne avec CapabilityBoundingSet= et AmbientCapabilities= vides : le serveur ne possède donc pas CAP_NET_BIND_SERVICE, et ne peut lier aucun port inférieur à 1024. Une configuration qui demanderait --listen [::]:25 échouerait au démarrage par « Permission denied ».

Les ports d'usage se ramènent donc sur des ports hauts par une redirection du pare-feu, en PREROUTING. Le fichier /usr/share/doc/air-mail-server/nftables-air-mail.conf.exemple en donne une table complète.

UsageRéelProtocole
25, 5872525SMTP, STARTTLS
4654465SMTP, TLS implicite
1431143IMAP, STARTTLS
9939993IMAP, TLS implicite
1101110POP3, STLS
9959995POP3, TLS implicite

Une redirection en PREROUTING ne voit pas la boucle locale. Un paquet né sur la machine traverse OUTPUT, non PREROUTING, et n'est donc pas redirigé : un programme local qui veut déposer du courrier doit viser le port réel (2525), et non le port d'usage (25), sous peine de Connection refused.

Et les ports hauts doivent être ouverts dans le pare-feu. La redirection ayant lieu avant le filtrage, la chaîne INPUT voit arriver du 2525 — pas du 25. Autoriser le 25 seul laisse tout passer jusqu'à la redirection, où tout est jeté, sans un mot dans le journal du serveur.

Le registre durcit la réception

Si la configuration nomme un registre de réception (--registre), un message n'est accepté qu'une fois son constat scellé et chaîné sur le disque. Quand le registre n'est pas écrivable, le serveur répond 451 et n'accepte plus rien : c'est voulu, un registre à trous ne prouverait rien.

Depuis la version 0.2.47, le serveur exige le mode 0700 sur ce répertoire et refuse de démarrer s'il est accessible aux autres comptes ou s'il ne pourrait pas y écrire. Il ne corrige plus le mode en silence, ce qu'il faisait auparavant.

Fichiers

/var/lib/air-mail/air-mail.conf

la configuration binaire, par convention. Son emplacement n'est fixé que par --config et par l'unité systemd.

/usr/lib/systemd/system/air-mail-server.service

l'unité livrée : compte air-mail, ProtectSystem=strict, appels système filtrés, ReadWritePaths=/var/lib/air-mail et aucune capacité.

/var/lib/air-mail

le répertoire d'état : boîtes, magasins, file d'attente, registre, journal d'audit, cache MTA-STS. Le seul chemin où le service peut écrire.

/usr/share/doc/air-mail-server/nftables-air-mail.conf.exemple

la table de redirection, en exemple. Elle n'est jamais installée d'office.

Diagnostics

Le code de sortie est 0 pour --help et --version, et non nul pour tout démarrage refusé. Les refus les plus fréquents, et leur cause réelle :

Permission denied

sur une écoute : un port sous 1024 — voir Ports ci-dessus.

refuse de démarrer

sur le registre : mode autre que 0700, ou propriétaire qui n'est pas celui du service.

451

à la réception : le registre n'est pas écrivable.

Connection refused

depuis la machine elle-même : vous visez le port d'usage au lieu du port réel.
